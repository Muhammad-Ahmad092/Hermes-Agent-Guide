## The defining shift

**April is when Hermes stopped being a terminal program.** Three graphical or
semi-graphical surfaces were born in a single month:

- **`ui-tui/` + `tui_gateway/`** — an Ink/React terminal UI with a Python
  JSON-RPC backend
- **`web/`** — the browser dashboard
- **`plugins/`** — the directory that would grow to hold providers, platforms,
  memory backends, and image generators

The TUI is the architecturally important one. It established the split that now
governs every surface: **TypeScript owns the screen, Python owns sessions, tools,
model calls, and slash-command logic**, talking newline-delimited JSON-RPC. The
desktop app (May) and the dashboard's chat tab both inherit that contract rather
than reinventing it.

The first TypeScript in the repo appears this month: 0 → 363 files.

## What shipped

### The TUI — 45 feature commits

`ui-tui/` (Ink/React) and `tui_gateway/` (Python JSON-RPC backend) arrive
together, tracked in the log as `Feat/ink refactor`.

Notable within the month: a live per-tool elapsed timer in the spinner, per-section
visibility for the details accordion, time-since-last-user-message alongside
session total, a subagent spawn observability overlay, LaTeX rendering, first-touch
onboarding hints ported from the CLI, and light-terminal auto-detection.

### The web dashboard

`feat: web UI dashboard for managing Hermes Agent`, then built out fast:

- React Router, sidebar layout, sticky header, dropdown components
- Themes expanded to fonts, layout, and density; reskin extension points for
  themes and plugins
- **Page-scoped plugin slots for built-in pages** — extensibility from day one
- Profiles management page; main + auxiliary model configuration from a Models page
- Skill analytics
- `--stop` and `--status` flags
- **i18n — English + Chinese**, with the dashboard UI improvements re-applied on
  top of it

### Kanban — the multi-agent board

`feat(kanban): durable multi-profile collaboration board` — a durable SQLite board
where a dispatcher claims tasks and spawns whole profiles as workers. This becomes
one of the largest subsystems in the tree, and May is almost entirely devoted to
maturing it.

### Plugins become a real system

`plugins/` is born as a directory, and the context surface grows:

- `dispatch_tool()` on `PluginContext`
- `transform_tool_result` hook for generic tool-result rewriting
- `pre_approval_request` / `post_approval_response` hooks
- `register_command()` on the plugin context
- `duration_ms` on `post_tool_call` and `transform_tool_result`
- **Pluggable `image_gen` backends** + an OpenAI provider — the first ABC +
  orchestrator + per-plugin-directory pattern
- Bundled plugins: `hermes-achievements` (with full session-history scanning),
  `google_meet` (join, transcribe, speak, follow up)

### Memory becomes pluggable

**`feat(memory): pluggable memory provider interface with profile isolation`** —
the `MemoryProvider` ABC, orchestrated by `agent/memory_manager.py`. Honcho, which
had been bespoke since February, becomes the first provider behind the interface,
and gets a context-injection overhaul with a 5-tool surface, cost safety, and
session isolation.

This is the canonical instance of the rubric's rule: *when 3+ PRs want to
integrate the same category of thing, design an ABC and turn them into plugins.*

### The curator matures

Per-run reports (`run.json` + `REPORT.md` under `logs/curator/`), archived split
into consolidated vs pruned with model + heuristic classification, most-used and
least-used skills in `hermes curator status`, and class-first review prompts with
active-update bias.

### Sessions, backup, and search

- **`hermes backup` and `hermes import`**, then SQLite-safety fixes plus `--quick`
  snapshots and a `/snapshot` command
- Backups exclude `checkpoints/` and SQLite WAL/SHM/journal sidecars
- **Trigram FTS5 index for CJK search**, replacing the LIKE fallback
- Auto-prune of orphan and stale shadow repos (checkpoints) at startup

### Agent behavior

- **`/goal` — persistent cross-turn goals (the Ralph loop)**
- `/compress <focus>` — guided compaction with a focus topic
- **`hermes -z <prompt>`** — one-shot mode, later gaining `--model` / `--provider`
- Native multimodal routing based on model vision capability
- `save oversized tool results to file instead of destructive truncation`
- Structured API error classification for smart failover
- Per-turn primary runtime restoration and transport recovery
- **Auto-continue interrupted agent work after gateway restart**
- Coerce tool-call arguments to match JSON Schema types
- `execute_code` project/strict modes, and execution on remote terminal backends
- Thinking-only prefill continuation for structured reasoning responses
- Progressive subdirectory hint discovery

### Observability

- **Centralized logging, instrumentation, `hermes logs` CLI**, gateway noise fix
- Component-separated logging with session context and filtering
- `hermes debug share` — upload a debug report to a pastebin
- `hermes dump` — copy-pasteable setup summary
- Config structure validation — detect malformed YAML at startup

### Approvals and safety

- **Hardline blocklist for unrecoverable commands**
- Approval buttons for Slack and Telegram; Feishu interactive card approvals
- OSV malware check for MCP extension packages
- Secret redaction toggled off by default (it flips back on in May)

### Platforms

BlueBubbles (iMessage) adapter, WSL-aware gateway with smart systemd detection,

native slash commands under a `/skill` group with category subcommands, shared

### Providers and models

Gemini CLI OAuth via Cloud Code Assist (free and paid tiers), GMI Cloud, Codex

Anthropic, rate-limit headers captured and shown in `/usage`, and a stream of
catalog additions (Kimi K2.6, MiMo v2.5, DeepSeek V4, GPT-5.5, Claude Opus 4.7,
elephant-alpha, owl-alpha).

### Browser

A CDP supervisor with dialog detection and cross-origin iframe eval, raw

Camofox sessions with VNC URL discovery, local Chromium auto-spawn for
LAN/localhost URLs in cloud mode, and a switch of managed provider from
Browserbase to Browser Use.

### CI and process

**`feat(ci): add contributor attribution check on PRs`** — the lane that still
gates every PR on a recognized author email.

### Skills — 37 feature commits

`hermes skills reset`, HTTP(S) URL installs, a skill config interface, comfyui
promoted from optional to built-in, plus a large creative wave: manim-video, p5js,
popular-web-designs (54 design systems), design-md, architecture-diagram,

growing context surface, backups and snapshots, centralized logging, and six

**What April did not have:** a native desktop app. `apps/desktop/` appears next
month and immediately becomes the largest area of work in the repo.

## Reading this month in today's code

- **The JSON-RPC surface split.** Established by the TUI, now the contract behind
  the desktop app, the dashboard's chat tab, and `hermes serve`.
- **"Do not re-implement chat in React."** The dashboard rule exists because April
  built both a React dashboard *and* an Ink TUI, and embedding the TUI proved
  better than maintaining two transcripts.
- **The ABC + orchestrator + plugin-directory pattern.** First applied to memory
  and image generation in April; later reused for model providers, platforms,
  context engines, and video generation.
- **The attribution CI lane.** April's process addition, still failing PRs today.
