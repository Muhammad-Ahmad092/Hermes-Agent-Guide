## The defining shift

Two things define March.

**First, it became a real released product.** On March 12:

```
feat: add versioning infrastructure and release script
chore: bump version to v0.2.0 + add curated first-release changelog
```

That is the first release in the project's history. Four more followed in the same
month. A "curated first-release changelog" means someone sat down and wrote what
this thing is for an outside audience.

**Second, and more structurally: March is when Hermes stopped being one program
and became a platform with extension points.** Three mechanisms arrived within
weeks of each other, and all three are still the primary way capability enters
the system:

- **MCP** — a native client, so any MCP server becomes a toolset
- **Profiles** — multiple fully isolated instances
- **Plugins** — lifecycle hooks, slash-command registration, install/remove CLI

Combined with 1,184 fix commits and a 6× jump in test files, March is the month
the project acquired both its extensibility and its engineering discipline.

## What shipped

### MCP — the whole client, in one month

Seven MCP features landed in March, going from nothing to a production client:

- **Native MCP client with HTTP transport, reconnection, and security**
- **MCP servers exposed as standalone toolsets** — the design that keeps them off
  the core schema
- Sampling support — server-initiated LLM requests
- Dynamic tool discovery via `notifications/tools/list_changed`
- Selective tool loading with utility policies
- MCP server management CLI + **OAuth 2.1 PKCE auth**
- `hermes mcp serve` — Hermes itself as an MCP server
- Interactive MCP tool configuration in `hermes tools`

### Profiles

**`feat: add profiles — run multiple isolated Hermes instances`**, plus a
`/profile` slash command. This introduced `_apply_profile_override()` and the
`get_hermes_home()` discipline that now governs every path in the codebase — and
the five bugs later fixed in PR #3575 for hardcoding `~/.hermes` are the direct
consequence.

### Plugins — the first surface

- Plugin lifecycle hooks activated (`pre`/`post_llm_call`, session start/end)
- Slash-command registration for plugins
- `hermes plugins install/remove/list`
- Enable/disable commands with an interactive toggle UI
- An `inject_message` interface for remote message injection

### Six new chat platforms

The gateway went from Telegram-plus-a-bit to a genuine multi-platform system:

| Platform | What landed |
|---|---|
| **Feishu/Lark** | Full platform support |
| **WeCom** (Enterprise WeChat) | Full platform support |
| **DingTalk** | Adapter + setup-wizard wiring |
| **Matrix** | Adapter, plus native voice messages via MSC3245 |
| **Mattermost** | Adapter, @-mention-only filter, configurable mention behavior |
| **Webhook** | Platform adapter for external event triggers |

Plus deepening on the existing ones: Slack multi-workspace via OAuth token file,
Slack formatting/reactions/user resolution, Discord `/thread` + auto-threading +
document caching + processing reactions + persistent DM typing indicators,
Telegram private chat topics with skill binding, group mention gating and regex
triggers, webhook mode as an alternative to polling, HTML auto-detection, and DoH
fallback IP discovery for when `api.telegram.org` is unreachable.

### An OpenAI-compatible API server

`feat: OpenAI-compatible API server` — then hardened within the month:
Idempotency-Key support, body size limits, an OpenAI error envelope, `/v1/health`,
CORS `Access-Control-Max-Age`, basic security headers, `/api/jobs` endpoints for
cron management, and tool-progress streaming to Open WebUI.

### Context management — the compaction era begins

- **Major context compaction improvements**
- **Context pressure warnings** for CLI and gateway
- Overhauled context-length detection with `models.dev` and provider-aware
  resolution; local-server context-window probing; Fireworks support
- **Replaced inline nudges with background memory/skill review** — the moment the
  learning loop moved off the critical path to stop breaking the prompt cache
- Priority-based context file selection + `CLAUDE.md` support
- Tool-use enforcement, made configurable, with budget warnings stripped from
  history
- `feat(gateway): cache AIAgent per session for prompt caching`

That last one is small in the log and large in effect: caching the agent per
session is what makes prompt caching work across gateway turns.

### Providers and resilience

- **Same-provider credential pools with rotation** + custom endpoint support
- **Ordered fallback provider chain**
- Eager fallback to a backup model on rate-limit errors
- GitHub Copilot, Hugging Face, Kilo Code, and Alibaba Cloud as first-class
  providers
- Route-aware pricing estimates; endpoint metadata for custom model context and
  pricing

### Identity, security, privacy

- **`SOUL.md` as the primary agent identity** instead of a hardcoded default
- PII redaction from LLM context (`privacy.redact_pii`)
- Tirith pre-exec command scanning
- Website blocklist enforcement for web and browser tools
- Pre-call sanitization and post-call tool guardrails
- `View full command` option on dangerous-command approval; configurable approval
  timeout

### Browser and web

- **`/browser connect`** — attach browser tools to a live Chrome via CDP
- Camofox local anti-detection backend; multi-provider cloud browsers + Browser
  Use integration
- Three new web backends: **Exa**, **Tavily**, **Parallel**

### Migration from OpenClaw

An entire migration path shipped this month: `hermes claw migrate`, a
comprehensive v2 migration with 17 new modules and terminal recap, migration
offered during the first-time setup wizard, and post-migration directory cleanup.

### CLI and UX

`@` context references and Claude-Code-style completions, file-path autocomplete,
two-stage `/model` autocomplete with ghost text, `/queue`, `/btw`, `/bg`,
`/plan`, `/yolo`, `/statusbar`, `/reasoning`, `/tools`, `/insights` (usage
analytics and cost estimation), session naming with unique titles and
auto-lineage, an interactive session browser, Ctrl+Z suspend, multiline paste
preservation, `NO_COLOR` and `TERM=dumb` support, and streaming on by default.

### Infrastructure

- **`acp_adapter/` is born** — the ACP server for VS Code / Zed / JetBrains, with
  slash-command support
- **`website/` is born** — the Docusaurus docs site, with a skills browse page
- **`optional-skills/` is born** — the heavier/niche tier
- **Nix flake** — uv2nix build, NixOS module, persistent container mode
- **Docker container** for the agent
- Skills: external skill directories via config, HTTP(S) URL installs, the
  skills.sh hub source, `garrytan/gstack` as a default tap, and ~12 new skills
  (Linear, X/Twitter, telephony, Docker management, blender-mcp, SiYuan,
  memento-flashcards, songwriting, NeuroSkill BCI, huggingface-hub, Canvas LMS,
  meme-generation)

## Where things stood at the end of March

Hermes was now a released, versioned product (v0.6.0) that ran on ~10 chat
platforms, spoke MCP in both directions, supported multiple isolated profiles,
had a plugin system with lifecycle hooks, exposed an OpenAI-compatible API, could
migrate users off a competitor, and shipped as a Docker container and a Nix flake.

Test files went 63 → 385. Python files went 208 → 631.

**Still missing:** any graphical surface. The CLI was the only interface. That
changes immediately — `ui-tui/`, `tui_gateway/`, and `web/` all appear in April.

## Reading this month in today's code

- **`_HERMES_CORE_TOOLS` vs MCP-as-toolsets.** March established the pattern that
  an MCP server costs zero core schema. It is now rung 5 on the Footprint Ladder.
- **Background review instead of inline nudges.** The single clearest example in
  the history of the cache invariant overriding a simpler design.
- **Credential pools and fallback chains.** Provider resilience became structural
  here, and `agent/credential_pool.py` plus `agent/error_classifier.py` are the
  descendants.
- **`SOUL.md`.** Agent identity as a user-editable file rather than a constant.
